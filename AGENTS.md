# AGENTS.md - fairtrade design system

Guidance for AI agents working in this repo. Humans: see `README.md`, plus the design record in
`DESIGN.md` (with `llm/NEUROINCLUSIVE.md` for the research behind its neuroinclusive rules) and
the product record in `PRODUCT.md`.

## what this is
A single-page presentation site for the **fairtrade** design system plus the component library
it documents. Stack: Vite 8 + React 19 + Tailwind v4 (CSS-first `@theme`) + Storybook 10. Package
manager: **pnpm**. Source is **JS/JSX only - no TypeScript**. Icons: `lucide-react`. Tables:
`@tanstack/react-table` (headless). Charts: `recharts` (wrapped, never raw).

## where things live
- `src/ui/*.jsx` - the component library; one component family per file, with a colocated
  `*.stories.jsx`. Import from the barrel: `import { Button } from './ui'`.
- `src/index.css` - the single source of truth for design tokens (`:root` dark + `[data-theme="light"]`)
  and every component's namespaced classes. Components emit class names; styling lives here.
- `src/sections-react/*.jsx`, `src/App.jsx` - the presentation page (not the library).
- `public/tokens.json`, `public/components.json` - generated machine-readable token + component
  manifests (DTCG-ish). Do not hand-edit; run `node scripts/gen-llm-artifacts.mjs`.
- `DESIGN.md` - the one design record (tokens, principles, colors, typography, layout, shapes,
  components, voice). Its YAML frontmatter is generated by `scripts/gen-llm-artifacts.mjs`; the
  note at the top of `DESIGN.md` says what is generated, what is authored, and where. Never edit
  the frontmatter by hand. The prose is authored.
  `llm/NEUROINCLUSIVE.md` - the research behind each of its neuroinclusive rules, one line per rule
  naming the rule, plus the review checklist; where the two disagree, `DESIGN.md` wins.
  `llm/DESIGN.md` is a pointer to `DESIGN.md`.
- `PRODUCT.md` - who the design system serves, what it owns, and its constraints (read by the
  `impeccable` skill before UI work here).

## commands
- `pnpm dev` - run the page (Vite, http://localhost:5180).
- `pnpm build` - generate llm artifacts + contrast gate (WCAG, both themes) + Vite build. Must pass.
- `pnpm test:design-decisions` / `pnpm audit:design-decisions` - named mutation tests and real-source decision/record audit; required by the library build.
- `pnpm storybook` / `pnpm build-storybook` - the component reference.
- `node scripts/sbsmoke.mjs` - load every story incl. `play()`; 0 real errors required.
- `node scripts/sbshot.mjs both shots/x <story-id-substr>` - screenshot stories (both themes) for QA.

## hard invariants (do not violate; the build gate enforces contrast)
Where the demo and one of these disagree, the Status note at the top of `DESIGN.md` says which
side a consumer matches.
- **Tokens only.** Never hardcode a hex/px - reference a token (`var(--amber)`, `var(--sp-4)`).
  Spacing is the 4/8 scale (`--sp-1..8`); icon sizes are `--ic-sm/md/lg`; controls share `--control-h`.
- **Radius 0** everywhere (square). **Amber is a scarce accent.** Palette is desaturated/earthy.
- **Two themes**, both must pass WCAG AA; everything re-themes by swapping CSS vars on `[data-theme]`.
- **16px floor** for readable body text; chrome/labels are mono 14. **All-lowercase UI chrome**;
  never lowercase user content (names, code, data values). **Tabular numbers** on counts/durations.
- **Neuroinclusive by default**: 1.5 line-height, >=24px hit targets, global focus ring,
  static-first motion (guard transitions with `prefers-reduced-motion`). Primary publish actions
  are 36px desktop / 44px coarse-pointer touch. On a coarse pointer every control height rises to
  44px; a small visual drawn at `--chip-h` takes a 44px hit box. The standard focus ring has one inset variant.
  Only the named busy-spinner may loop during work when motion is allowed. See `DESIGN.md`.
- **Semantic meaning is never carried by colour alone** - always pair an icon or text label.
- **Real brand logos**: when naming a company/provider (claude, gemini, openai, cursor, opencode, strike),
  lead with `<BrandMark name="..." />` (or `<Tag brand="...">`), never a generic glyph.
  The github account row also leads with its brand mark; navigation itself is text-first.
- **No AI-slop** in copy or UI: no em dashes, no buzzwords, no `//` markers, no eyebrow labels,
  no middot separators, no `>` prefixes (except the nav active marker). Namespaced classes; no generic collisions.

## release & npm publication

Titles carry intent only; the release job computes every number. Write a PR
title as `type(scope)[level]: subject` with a bracket on every releasing title
(`feat`, `fix`, and `release` always; `refactor`, `perf`, `build`, and `revert`
only when they release): `feat(transcript)[minor]: add group facet`,
`fix[patch]: typo in the empty state`, `release[patch]: publish the pending
deps bumps`. Scopes are free-form. Below 1.0 a breaking change is `![minor]`;
`![patch]`, `![major]`, and `[major]` are rejected, and no title ever mints
`1.0.0`. Never write a version, a CHANGELOG entry, or a spec number: the bot
owns `CHANGELOG.md` as a whole file and the `version` field of `package.json`.
An author PR that touches either fails `title-guard` with `protected-path`;
other `package.json` fields stay ordinary content. `title-guard.yml` checks the
live title, author, and SHAs on every pull-request event and again in every
merge-group build, and refuses an unidentified group entry closed rather than
letting it land unchecked.

Every PR lands through the batched native merge queue (squash). `ci.yml` runs
on `merge_group` with per-ref concurrency (cancelled only on `pull_request`).
The `lib` job builds `pnpm prepack` on the release PR and `pnpm run build:lib`
everywhere else, decided by `release-intent classify` from author and head
branch, never by a title or branch literal. `pnpm test:lib` runs the library
tests, mutations, and built Pi rendering check in CI after building the artifact.
To retitle a queued PR, remove it from the queue first, edit the title, then
enqueue again: the queue build re-checks the new title before it can land.

One standing bot release PR (`automation/release`, opened by
`peasant-labs-releaser[bot]`) carries the CHANGELOG section and the version
field, lands through the queue by auto-merge, and is rebuilt after every
landed batch. `.github/workflows/release-batch.yml` is the one serialized job
that keeps it current, tags its landed commit, and publishes the GitHub
Release in the same tag step: it plans from the branch tip with the
release-intent tool, pushes the computed tag on a fresh candidate, creates or
updates the Release from the generated notes, and opens, updates, arms,
holds, or closes the release PR exactly as the plan says. It arms auto-merge
only while no releasing PR is ahead in the queue; on hold it only turns
auto-merge off, and a queued release PR is never dequeued. A release commit
whose content went stale is never tagged; the next run rebuilds the release
PR instead. Nothing pushes to `main` outside the queue, and no hand, bot, or
agent pushes or edits the release PR or its branch. With
nothing to change, force a release through the queue, either as an empty-commit
PR titled `release[<level>]: cut a release` or with the `cut-release.yml`
`workflow_dispatch` button (`patch` or `minor`), which opens that PR for the
requesting maintainer with auto-merge on. Do not create manual tags for future
releases and never move or delete a release tag; a failed publish burns its
number and the fix is forward. `RELEASE_BATCH_MODE` stays unset until the
operator has checked the first landed group, and while it is unset the job
only prints its plan.
**Pushing the App-authenticated tag publishes**: `.github/workflows/npm-publish.yml` runs `prepack`
(package metadata validation, `build:lib`, and tarball-content checks) and publishes `@peasant-labs/fairtrade` via **npm
Trusted Publishing (OIDC)** - no `NPM_TOKEN` secret exists. `pnpm
test:package-provenance` keeps the package's canonical repository metadata exact. npm
generates provenance automatically only when this source repository is public; private
source repositories remain unattested even though OIDC authentication succeeds. A
prerelease version (`-rcN` etc.) lands under dist-tag `next`; a final under `latest`. The
workflow refuses a tag whose version does not match `package.json`, reports the expected
missing attestation while this repository is private, and hard-fails after publication if
a public-source release lacks the SLSA provenance predicate.

**The same App-authenticated tag also runs `.github/workflows/release.yml`**, independently of
`npm-publish.yml`: a `guard` job classifies the tag with `release-guard.mjs parse-tag` (version +
`kind`, `rc` or `final`), then a `release` job extracts the matching `## X.Y.Z[-rcN]` CHANGELOG.md
section with `scripts/release-notes.mjs`, appends a line naming the published npm package version,
and refreshes the Release notes with `gh release edit` (the release job's tag step created the
Release when it pushed the tag). A tag without a matching CHANGELOG section fails this job with an actionable error;
only the bot release PR writes that section, so fix the release content forward
and let the job tag the corrected commit.

One-time maintainer registrations (registered state lives on npmjs.com/GitHub, not in-repo):
(1) install the releaser GitHub App on `peasant-labs/fairtrade-design-system` with Contents write
permission and configure Actions secrets `PEASANT_RELEASER_APP_ID` and
`PEASANT_RELEASER_APP_PRIVATE_KEY`; (2) a `npm-publish` GitHub Actions **environment** on this
repo; (3) on npmjs.com,
this repo + `npm-publish.yml` + that environment registered as the package's **Trusted
Publisher**. Never add a token secret as a fallback; if OIDC exchange fails, fix the
registration. Also maintainer-side: repository setting `allow_auto_merge` on, squash commit
title `PR_TITLE`, the `Merge queue` ruleset on `main` (required contexts `lib`, `gates`,
`title-guard`, compared with `.github/release-guard.policy.yml`), and
`RELEASE_BATCH_MODE=tag` after the first landed group is checked.
